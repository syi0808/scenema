# Scenema Color Palette

Scenema uses warm neutral surfaces to feel like a precise working instrument rather than a generic developer-tool landing page. Blue communicates the one active path. Status colors communicate outcomes only.

## Semantic Tokens

| Token            | Value     | Use                                     |
| ---------------- | --------- | --------------------------------------- |
| `canvas`         | `#f3f1eb` | Page background                         |
| `surface`        | `#fcfbf7` | Demo chrome and quiet sections          |
| `surface-strong` | `#ffffff` | Working product area                    |
| `ink`            | `#17191d` | Primary copy and strong structure       |
| `muted`          | `#62635f` | Supporting copy and metadata            |
| `line`           | `#d6d2c8` | Dividers and control borders            |
| `line-strong`    | `#aaa69d` | Product frame and emphasized borders    |
| `action`         | `#2450e6` | Primary action, focus, active demo step |
| `action-hover`   | `#193ec0` | Primary action hover                    |
| `action-text`    | `#ffffff` | Text on action surfaces                 |
| `success`        | `#147a4b` | Confirmed completion and ready status   |
| `danger`         | `#b63b32` | Errors and recovery guidance            |

## Usage Rules

- Keep blue to one primary focal point per component or viewport.
- Use status colors only when a state has actually changed.
- Use warm borders for structure instead of shadows or alternating gray cards.
- Keep the default site light until a complete dark palette is designed and tested.
- Confine code syntax colors to the dark code panel.
- Never use a full-width black or blue band as decorative emphasis.
